## What exists now

Two different apps are in git. Only one is on `main`.

**`main` (`ae6012b`)** is a Python FastAPI service plus a small server-rendered demo.

- Rank demo: `python -m aeo.ranksim serve` (default port 8765). Routes on `main`: `GET /`, `GET /space`, `POST /check`. HTML is built in `src/aeo/ranksim/demo.py`. It can paste a draft, score it against stored pages, and show a competitor space view.
- Labels already in that demo: REAL positions from the stored file, PREDICTED ranks among stored pages, `PREDICTED n/a` when HTML is missing, confidence `UNSURE` when the gap is small.
- Older AEO API: `uvicorn aeo.main:app` on port 8741. That product is parked.
- Demo data in the private repo: `smartcrew/serp.csv` (135 labeled rows, 16 queries), `smartcrew/saved_html/`, `smartcrew/pr8_v3/`, `smartcrew/competitors.csv`. The SERP file does not record a pull date. It is a historical SmartCrew export, not a live Google result.
- Tests on `main`: 63 passed with no provider keys (earlier run on this repo). One test fails if `OPENROUTER_API_KEY` is set, because it does not clear that setting. That fix is not in this commit.

**Claude's branch `claude/bold-einstein-oi5qoj` (`35dc82a`, 2026-11-04, no pull request)** is the real UI work.

- Same command, `python -m aeo.ranksim serve`, bound to `127.0.0.1` by default. Binding `0.0.0.0` is possible and prints that there is no login.
- Server-rendered pages, one CSS file and a small job-polling script inside `serve.py`. Viewport meta tag is present. One layout breakpoint at 600px. Content width 980px.
- Flows already described in that branch's README: create a project (site plus searches), import a `query,url,position` CSV, pull (Google step says `not run` without a paid SERP key and can reuse an import), paste or upload HTML, see a result board, compare saved versions.
- REAL and PREDICTED are separate labels. Missing keys render as `not run: needs <ENV VAR>`. AI engine calls and the LLM simulation are off unless a key is set, and the UI is written to show that state.
- Claude's own accuracy note on that branch: the content model is not better than a simple baseline on this SmartCrew file, and the page says so. An optimize/rewrite loop exists for the older tester and is not wired into projects for that reason.
- `main` does not contain this UI. Merging it is Claude's branch, not this design branch.

## Deployability

There is no public Ranksim URL, and this pass did not create one.

| Piece | Fact |
| --- | --- |
| Ranksim UI hosting | Not set up. Claude's README lists hosting as not built. |
| `Dockerfile` | Python 3.12 image. Command is `uvicorn aeo.main:app` on port 8741. That is the parked AEO API, not `ranksim serve`. |
| `docker-compose.yml` | Postgres with pgvector, API, and worker for that AEO API. Default providers are mock. It does not publish the rank demo. |
| CI, Vercel, Fly, Render, GitHub Actions | None in the repo. |
| Auth | None. A non-loopback bind is an open tool. |
| Data | SmartCrew pages, queries, and competitor URLs are already in this private GitHub repo. A public site would publish that client corpus. |

Smallest deployment that is honest:

1. Today: run Claude's UI locally with `python -m aeo.ranksim serve` and no API keys. James uses his own machine. No new account, no new bill, no public host.
2. Later, only if James wants a URL: one private process he already controls (`ranksim serve` on loopback, reached by an SSH tunnel or an existing private host). Do not switch today's Docker Compose into a public service. Do not buy a host from this work. Do not put the SmartCrew corpus on the public internet.

Blockers for an "accessible deployment URL" today: no login, no ranksim container, no host James has asked us to use, and the demo dataset is client data.

## Approved scope, UI owned by Claude

James approved this walkthrough. Claude implements it on `claude/bold-einstein-oi5qoj`. SEO Tool Builder does not start a second frontend. Reuse the Python ranker. Do not add billing, accounts for many customers, or any promise of an exact Google rank.

End-of-day walkthrough, keyless, on the historical SmartCrew file:

1. Open the app and see an empty state that says what to do next.
2. Load that file as a labeled demo ("historical SmartCrew export, pull date not recorded"), not as a live rank.
3. Pick one query. Show observed (REAL) order beside PREDICTED order for the same stored candidates. Missing HTML is `n/a`, not a guessed page. Low-confidence calls stay `UNSURE` or an equally plain warning already used on the board.
4. Paste one saved draft and compare it against those same candidates.
5. Improvement panel lists only checks the model can support. If the content model is no better than the baseline, the panel says that. It does not recommend AI rewrites.
6. With no provider keys, every AI and live-SERP control says unavailable and does not call out.
7. Loading, empty, and error states are visible (no project, bad paste, missing file, job failure).

Claude proves it in a browser at 375, 768, and 1440. A public URL stays out of scope until the data and login blockers above are accepted. Exact private-host command: `docs/BACKEND_CONTRACTS.md`.
